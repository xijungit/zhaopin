## 1. 体系概述与商业定位

### 1.1 业务背景与用户画像
当前校招求职市场（秋招、春招、日常实习）具有强烈的**时间敏感性**与**信息不对称性**：
- **目标客群**：普通高校及重点院校应届本科生、硕士生、海外留学生，以及备战名企校招转正的在校求职群体。
- **用户核心痛点**：
  1. 职位信息零散，海投命中率低，急需名企官方**内推码**与**直聘通道**；
  2. 笔试通过率低，缺乏高质量、带答案解析的**大厂历年笔试测评真题卷**与**人才引进政策**；
  3. 面试缺乏针对性复盘，大厂**高频核心考点**与**STAR 题解**零散分散于网络各处；
  4. 传统求职培训动辄上千上万元，学生群体支付意愿弱，但对**低客单价、高信息密度、开箱即用**的数字资产具有极高的付费冲动。

### 1.2 商业化破局思路与变现痛点
针对学生群体“对大额充值警惕，对低价刚需果断，对单篇零散扣费嫌麻烦”的心理特征，系统确立了**“超低门槛引爆单量 + 终身免积分极致体验 + 闲鱼淘宝卡密多点分销”**的商业化策略：
- **拒绝高价门槛**：不设置数百元的传统年卡，采用 **9.9 元（结缘价）** 击穿心理防线，将付费转化率从传统模式的 1%~2% 提升至 15%~25% 以上；
- **解决信任问题**：新用户注册直接赠送 100 积分，可免费体验单篇解锁，建立平台内容品质信任后再引导升级终身 VIP；
- **全域获客矩阵**：不仅在自营 Web/H5 站内转化，还通过闲鱼、淘宝、拼多多、自动发卡平台售卖电子卡密，将电商自然搜索流量无缝导入系统。

### 1.3 “三位一体”商业模型（终身VIP + 积分钱包 + 电商卡密）
整个商业收费体系由以下三大支柱有机融合构成：

| 用户等级/角色 | 标识字段与取值 | 获取条件 | 核心定位 |
| :--- | :--- | :--- | :--- |
| **游客访客** (Guest) | 未登录 (Session Null) | 访问平台首页 | 浏览岗位与公开摘要，感受平台价值，建立初印象 |
| **普通注册会员** (Member) | `role='member'`<br>`is_treasure_vip=0` | 免费注册账号（手机/邮箱） | 获得 100 初始积分，可参与邀请裂变，按需解锁单篇内容 |

| **超级管理员** (Admin) | `role='admin'` | 环境变量 / 数据库指定 | 拥有全局免权限查阅特权，管理官网爬虫，生成并导出卡密 |

## 3. 核心变现模块与交互设计 (UX/UI)

### 3.1 “藏宝阁”高价值专区业务聚合
在系统主导航栏，将高价值的数字内容统一归集入“🏰 藏宝阁 (Treasure)”版块（位于第 4 Tab），形成强大的商业变现聚集地：
- **面经复盘子 Tab (`ExperiencesView`)**：收录阿里、腾讯、美团、字节、华为、百度等 700+ 篇深度面试经验，覆盖算法技术、产品策划、运营等岗位，带 STAR 场景问答；
- **真题资料子 Tab (`ResourcesView`)**：收录各大厂历年机试、测评题库、通用能力测试卷与 23 条重点省市青年人才补贴政策，附带真实网盘链接与提取码；
- **VIP 身份状态条**：
  - 未开通状态：顶部 Banner 呈深紫金色，提示“🏰 待激活 · 9.9元结缘解锁”，附带金色开启按钮；
  - 已开通状态：自动切换为辉煌流金渐变背景，佩戴“👑 金牌会员 · 已激活终身特权”勋章，并显示“✨ 财富法门已开启！大厂深度面经复盘与校招笔试真题全场免积分无限制查阅”。

### 3.2 卡通萌龙 IP 门禁与心理学促转化设计
为了避免传统付费弹窗冷冰冰的商业推销感，系统原创打造了“藏宝阁机缘神兽 · 小蓝龙”萌宠 IP (`TreasureLockModal.jsx`)：

```
                  ┌───────────────────────────────┐
                  │    🏰 藏宝阁机缘守护使 (小蓝龙) │
                  │     [ 3.5s 悬浮呼吸动态光环 ]   │
                  └───────────────┬───────────────┘
                                  │
                                  ▼
    ┌───────────────────────────────────────────────────────────┐
    │  “你是否希望用 9.9 元激活藏宝阁？这 9.9 元不是买卖，是你  │
    │   开启财富法门的钥匙。买不了吃亏，买不了上当，只为筛选有缘人。” │

- **视觉动效渲染**：
  - CSS 关键帧 `@keyframes dragonFloat` 实现萌龙在空中呼吸沉浮（3.5 秒周期）；
  - 配套 `mascot-aura` 与 `mascot-glow-ring` 金色渐变光晕与脉冲波纹扩散动效；

### 3.3 支付收银台体验与双渠道扫码
系统支持在同一界面内平滑切换多种支付形态：
1. **微信与支付宝双通道随时切换**：
   - 默认选中微信支付（绿色胶囊），可一键切换支付宝（蓝色胶囊）；
   - 切换渠道时，动态展示对应的预设二维码资产（`/assets/pay_wechat_99.png` 与 `/assets/pay_alipay_99.jpg`），金额预设为 ¥9.90，无需用户手动输金额；
2. **“双保险”支付完成机制**：
   - **自动化轮询保底**：前端启动 1500~2000ms 定时器持续轮询 `GET /api/pay/query?orderId=...`；
   - **用户自助确认（秒级闭环）**：提供绿色醒目按钮“✅ 我已完成扫码支付，立即开通”，用户付款后点击直接调用 `POST /api/pay/self-confirm`，无缝入账升级，彻底杜绝个人收款码无回调导致的流失。

### 3.4 个人中心与虚拟资产展示
在“👤 我的中心”构建了一站式用户数字资产看盘：

  - 头像首字大圆标、账号信息、个性化昵称轻量修改（✏️ 修改）；
  - 若已开通 VIP，展示流光溢彩的“👑 藏宝阁终身 VIP 会员”卡片；
- **积分钱包仪表盘**：
  - 醒目大字展示“账户剩余可用积分：**100 分**”，附带【充值 / 卡密兑换】快捷入口；
- **三大分类子内容抽屉**：
  - `📁 已解锁内容`：历史兑换过的所有面经全文与题库网盘提取码永久存档；
  - `🎁 邀请有礼`：展示专属邀请码、已邀请人数、一键复制专属裂变文案与短链；
  - `📜 积分明细流水`：记录注册赠送、充值到账、卡密兑换、邀请奖励、消费扣减的全流程收支账单。

## 4. 积分经济学模型与增长裂变机制

### 4.1 积分获取链路（Issuance Loop）

                └──────────────────────┬───────────────────────┘
                                       │
     ┌──────────────────┬──────────────┴─────┬──────────────────┐
     ▼                  ▼                    ▼                  ▼
┌──────────────┐ ┌──────────────┐     ┌──────────────┐   ┌──────────────┐
│  新用户注册  │ │ 邀请好友注册 │     │ 在线套餐充值 │   │  电商卡密兑换│
│ (+100 积分)  │ │ (+50 积分/人)│     │(500~3500分)  │   │ (+750 积分)  │
└──────────────┘ └──────────────┘     └──────────────┘   └──────────────┘
```

1. **新人迎新大礼包**：
   - 用户注册成功即可获得 **100 初始积分**；
   - 价值对标：可免费解锁 20 篇大厂面试经验，或 10 套完整名企笔试真题试卷；
2. **邀请裂变双向激励**：
   - 邀请人获得 **+50 积分/人**；
   - 被邀请人额外再获得 **+50 积分**（注册总共到手 150 积分）；
3. **商业充值与卡密兑换**：
   - 在线充值：¥10=500分、¥20=1200分、¥50=3500分；
   - 卡密兑换：单张卡密标准发行 750 积分。

### 4.2 积分消耗链路（Consumption Loop）
针对未升级 VIP 的普通会员，设置清晰的按件计费定价：
- **面经复盘单篇解锁**：每篇消耗 **5 积分**（`points_required: 5`）；
- **笔试真题与人才政策解锁**：每套消耗 **10 积分**（`points_required: 10`）；
- **永久归档机制**：
  - 用户一旦成功扣减积分，系统写入 `user_unlocks` 唯一记录表（`UNIQUE(user_id, target_type, target_id)`）；
  - 后续该用户在任何设备重新访问该内容，均直接返回完整内容，**绝不二次扣分**；
- **VIP 用户降维打击**：
  - 拥有 `is_treasure_vip = 1` 的用户，系统鉴权直接通过，**扣分金额恒等于 0**。

### 4.3 邀请裂变系统（Growth Flywheel）
系统通过自动化 URL 参数追踪与轻量口令实现零成本自传播：
1. **短链自动绑定**：
   - 邀请链接格式：`https://zhaopin.qujin.vip/?ref=INVITE_CODE`；
   - 前端识别 URL 中的 `ref` 参数，在用户唤起注册弹窗时自动静默回填至“邀请码”表单项；
2. **一键生成社交裂变文案**：
   > “同学你好！推荐你使用这个【2027名企校招内推与题库大全】，最新大厂/央国企官网实时同步，注册即送100积分，点击链接免费领取：https://zhaopin.qujin.vip/?ref=Z8K9M2P1”
3. **防作弊设计**：
   - 数据库唯一邀请码索引 `idx_users_invite_code`；
   - 注册时基于账号（手机/邮箱）唯一性约束 `UNIQUE(account)`；
   - 同一账号无法自我邀请或循环嵌套邀请。

## 5. 第三方电商卡密体系与分销闭环

### 5.1 电商多渠道分销布局
针对淘宝、闲鱼、拼多多、小红书等平台求职资料搜索量大的特性，卡密系统可实现“全自动静默成交”：
- **买家路径**：买家在闲鱼下单拍下《2027大厂秋招题库礼包（内含750积分卡密）》；
- **自动发货**：卖家/自动发货助手通过消息自动发送一条 16 位卡密 `ZPIN-XXXX-XXXX-XXXX` 与网站地址；
- **用户核销**：用户打开网站，登录后进入个人中心 -> 输入卡密 -> 点击【立即兑换】 -> 750 积分秒级到账。

### 5.2 卡密生成算法与安全编码规范
系统卡密编码严格杜绝暴力破解与肉眼识别混淆：
- **编码格式**：`ZPIN-[Chunk1]-[Chunk2]-[Chunk3]`（例如：`ZPIN-8XFA-K92P-M7HQ`）；
- **字符集过滤**：采用去除易混淆字符（数字 `0`、字母 `O`、数字 `1`、字母 `I`）的 Base-32 字符集：
  ```
  ABCDEFGHJKLMNPQRSTUVWXYZ23456789 (共 32 个字符)
  ```
- **熵值安全性**：
  - 每一个 Chunk 包含 4 个字符，3 个 Chunk 共有 12 个随机字符；
  - 密钥空间：32^12 ≈ 1.15 × 10^18 种可能排列；
  - 利用 Web Crypto API `crypto.getRandomValues(bytes)` 生成真随机字节，彻底防止伪造与碰撞。

### 5.3 批量制卡与 CSV 自动化发货
在管理后台提供便捷的卡密流水线工坊 (`AdminView.jsx`)：
1. **参数配置项**：
   - 单张面值金额：默认 10.00 元；
   - 兑换点数：默认 750 积分；
   - 单次制卡数量：1 ~ 500 张；
   - 批次标识（Batch ID）：如 `TB_202610`、`XY_CAMPUS_01`；
   - 渠道标签（Channel Tag）：如 `xianyu`、`taobao`、`pinduoduo`；
2. **一键导出发卡 CSV**：
   - 管理端点击生成后，系统分批写入 D1 数据库；
   - 前端一键生成标准 UTF-8 CSV 文件下载（包含字段：卡密兑换码、面值、积分、生成批次、渠道），无缝导入淘宝阿奇索、闲鱼自动发货助手等软件。

### 5.4 兑换核销链路与防吞码机制
兑换卡密接口严格遵循“预占验证 -> 状态变更 -> 账户充值 -> 异常自动反向回滚”的健壮逻辑，绝不出现卡密失效却未充值、或一次卡密被重复兑换两次的致命 Bug。

## 6. 系统数据模型与数据库设计 (D1 SQLite)

整个收费与会员体系依托于 Cloudflare D1 边缘关系型数据库（SQLite 引擎），经过 `0001`、`0004`、`0011` 等单调递增版本化迁移。

### 6.1 用户基础与权益表 (`users`)
存储用户认证、积分钱包与 VIP 状态：

```sql
CREATE TABLE IF NOT EXISTS users (
  id TEXT PRIMARY KEY,                       -- UUID 用户主键
  account TEXT NOT NULL UNIQUE,              -- 登录账号 (手机/邮箱)
  display_name TEXT NOT NULL,                -- 展示昵称 (脱敏保护，拒绝密码残留)
  password_salt TEXT NOT NULL,               -- PBKDF2 随机盐值
  password_hash TEXT NOT NULL,               -- 10,000 次哈希摘要
  role TEXT NOT NULL DEFAULT 'member',       -- 角色：member(普通用户), admin(管理员)
  points INTEGER NOT NULL DEFAULT 100,       -- 积分钱包余额 (初始 100)
  invite_code TEXT,                          -- 专属 8 位裂变邀请码
  referred_by TEXT,                          -- 邀请人用户 ID (外键关联 users.id)
  is_treasure_vip INTEGER NOT NULL DEFAULT 0,-- 藏宝阁 VIP 标识：0-未激活，1-已激活终身特权
  treasure_vip_activated_at TEXT,            -- 终身 VIP 激活时间 (ISO-8601)
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX IF NOT EXISTS idx_users_account ON users(account);
CREATE UNIQUE INDEX IF NOT EXISTS idx_users_invite_code ON users(invite_code);
```

### 6.2 支付交易订单表 (`payment_orders`)
记录在线充值与 9.9 元 VIP 购买全生命周期状态：

```sql
CREATE TABLE IF NOT EXISTS payment_orders (
  id TEXT PRIMARY KEY,                       -- 订单编号：ORD_... 或 VIP_...
  user_id TEXT NOT NULL,                     -- 下单用户 ID
  points INTEGER NOT NULL,                   -- 充值对应积分 (VIP 订单为 990)
  amount_cents INTEGER NOT NULL,             -- 支付金额 (单位：分，9.9元=990)
  channel TEXT NOT NULL,                     -- 支付渠道：wechat(微信), alipay(支付宝)
  status TEXT NOT NULL DEFAULT 'pending',    -- 状态：pending(待付), paid(已付), canceled
  qr_code_url TEXT,                          -- 展示的收款码本地图片路径
  channel_trade_no TEXT,                     -- 外部支付单号或核销凭证 (SELF_CONFIRMED)
  order_type TEXT NOT NULL DEFAULT 'points', -- 订单类型：points(积分充值), treasure_vip(藏宝阁VIP)
  paid_at TEXT,                              -- 支付完成时间
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);

CREATE INDEX IF NOT EXISTS idx_orders_user ON payment_orders(user_id, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_orders_status ON payment_orders(status);
```

### 6.3 积分流水账本表 (`points_ledger`)
金融级不可篡改的单向增量流水表，保证每一分钱、每一分积分收支都有迹可循：

```sql
CREATE TABLE IF NOT EXISTS points_ledger (
  id TEXT PRIMARY KEY,                       -- UUID 流水单号
  user_id TEXT NOT NULL,                     -- 用户 ID
  amount INTEGER NOT NULL,                   -- 变动量 (+50, -5, +500, 0)
  balance_after INTEGER NOT NULL,            -- 变动后账户最终积分余额
  action_type TEXT NOT NULL,                 -- 行为类别 (见枚举定义)
  related_id TEXT,                           -- 关联业务 ID (订单号/被邀请人ID/文章ID/卡密ID)
  remark TEXT NOT NULL,                      -- 账本摘要说明 (展示给用户查看)
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);

CREATE INDEX IF NOT EXISTS idx_points_ledger_user ON points_ledger(user_id, created_at DESC);
```

> **`action_type` 行为枚举说明**：
> - `register_reward`：新用户注册欢迎礼 (+100)
> - `invite_reward`：成功邀请好友注册奖励 (+50)
> - `recharge`：在线充值积分到账 (+500 ~ +3500)
> - `redeem_code`：兑换电商卡密到账 (+750)
> - `unlock_experience`：解锁名企面经扣除 (-5)
> - `unlock_resource`：解锁真题资料扣除 (-10)
> - `treasure_vip_activation`：9.9元激活藏宝阁终身会员权益流水 (0变动记录)

### 6.4 卡密兑换与批次表 (`redemption_codes`)
存储批量生成的卡密及其兑换状态：

```sql
CREATE TABLE IF NOT EXISTS redemption_codes (
  id TEXT PRIMARY KEY,                       -- UUID 卡密记录标识
  code TEXT NOT NULL UNIQUE,                 -- 16 位卡密字符串：ZPIN-XXXX-XXXX-XXXX
  batch_id TEXT NOT NULL,                    -- 批次名称 (如 BATCH_202610_XY)
  points INTEGER NOT NULL,                   -- 兑换可得积分 (默认 750)
  face_value_cents INTEGER NOT NULL,         -- 卡密面值 (单位：分，默认 1000)
  status TEXT NOT NULL DEFAULT 'unused',     -- 状态：unused(未用), used(已兑换), void(作废)
  used_by TEXT,                              -- 兑换者用户 ID
  used_at TEXT,                              -- 兑换时间
  expires_at TEXT,                           -- 过期截止时间 (可选)
  channel_tag TEXT,                          -- 渠道标示：xianyu, taobao, pdd
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (used_by) REFERENCES users(id) ON DELETE SET NULL
);

CREATE UNIQUE INDEX IF NOT EXISTS idx_redemption_code ON redemption_codes(code);
CREATE INDEX IF NOT EXISTS idx_redemption_batch ON redemption_codes(batch_id, status);
```

### 6.5 资源解锁记录表 (`user_unlocks`)
记录用户已付费解锁的内容，确保一次扣费、终身免费再次访问：

```sql
CREATE TABLE IF NOT EXISTS user_unlocks (
  id TEXT PRIMARY KEY,                       -- UUID 记录 ID
  user_id TEXT NOT NULL,                     -- 用户 ID
  target_type TEXT NOT NULL,                 -- 资源类型：'experience'(面经), 'resource'(题库/政策)
  target_id TEXT NOT NULL,                   -- 关联资源的主键 ID
  points_spent INTEGER NOT NULL,             -- 当时扣除的积分数
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(user_id, target_type, target_id),   -- 复合唯一键，彻底杜绝重复扣费
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);

CREATE INDEX IF NOT EXISTS idx_unlocks_user ON user_unlocks(user_id, target_type);
```

### 6.6 内容资源计费控制字段
面经表与题库表内建收费控制字段：
- **`interview_experiences`**：
  `points_required INTEGER DEFAULT 5`（单篇阅读所需积分）；
- **`resource_materials`**：
  `points_required INTEGER DEFAULT 10`（下载网盘资料所需积分）。

## 9. 高并发并发控制与财务安全机制

### 9.1 SQL 级别乐观锁防刷机制
电商卡密极易遭遇脚本重放攻击或同一卡密被多个客户端同时发起兑换。系统杜绝了传统的“先查后更”模式，采用 **SQL 级别单语句状态抢占（CAS 思想）**：

```javascript
const updateResult = await env.DB.prepare(
  `UPDATE redemption_codes 
   SET status = 'used', used_by = ?, used_at = CURRENT_TIMESTAMP 
   WHERE code = ? AND status = 'unused'`
).bind(user.user_id, rawCode).run()

if (updateResult.meta.changes === 0) {
  return Response.json({ error: '手慢了，该卡密刚刚已被他人兑换！' }, { status: 409 })
}
```
**原理解析**：即使 100 个并发线程同时执行该语句，底层 SQLite 在写操作互斥锁下仅会允许第一条语句更新生效（`changes = 1`），其余 99 条语句全部因 `status` 已变为 `used` 而命中 `changes = 0`，瞬时熔断拦截。

### 9.2 分布式故障反向补偿与自动回滚
在卡密已成功修改为 `used` 后，若后续向 `users` 表充值积分或写入 `points_ledger` 发生任何异常（如数据库超载、超时），系统内置 `try...catch` 自动执行**反向补偿事务**：

```javascript
try {
  await env.DB.batch([
    env.DB.prepare('UPDATE users SET points = ? WHERE id = ?').bind(newBalance, user.user_id),
    env.DB.prepare('INSERT INTO points_ledger ...').bind(...)
  ])
} catch (err) {
  // 触发反向补偿机制：将卡密重置回 unused 状态，杜绝“吞码”
  await env.DB.prepare(
    "UPDATE redemption_codes SET status = 'unused', used_by = NULL, used_at = NULL WHERE code = ?"
  ).bind(rawCode).run()
  return Response.json({ error: '兑换入账异常，已自动回滚卡密状态，请重试' }, { status: 500 })
}
```

### 9.3 Cloudflare D1 Batch 原子事务写入
针对支付激活与积分充值，系统严格采用 `env.DB.batch([...])`：
- **VIP 订单激活事务**：
  1. `UPDATE payment_orders SET status = 'paid', paid_at = CURRENT_TIMESTAMP`
  2. `UPDATE users SET is_treasure_vip = 1, treasure_vip_activated_at = CURRENT_TIMESTAMP`
  3. `INSERT INTO points_ledger (..., 'treasure_vip_activation', ...)`
- 三条语句在单次事务提交中完成，若任何一步失败则全量撤销，保障财务账本与用户状态绝对强一致。

### 9.4 支付防重复与幂等控制
- 订单初始状态为 `pending`；
- 在执行确认前，先执行 `if (order.status === 'paid') return ...` 幂等短路；
- 前端轮询与手动确认双向并发时，任何一方完成后，另一方即时感知并直接返回成功，不产生二次入账。

### 9.5 用户隐私脱敏与安全防御
- **密码哈希防破解**：密码采用 Web Crypto PBKDF2 算法，结合 256 位独立 Salt 与 10,000 次 SHA-256 哈希运算存储，绝对杜绝明文泄露；
- **防信息残留**：在注册与个人中心逻辑中，代码硬核校验 `if (!rawDisplayName || rawDisplayName === password)`，绝不允许将密码作为昵称保存或回显；
- **展示脱敏**：默认昵称自动使用邮箱前缀（如 `user@qq.com` 截取为 `user`）或系统通用称谓，个人中心接口绝不返回任何密码字段或哈希串。

## 10. 运营策略与未来演进建议

### 10.1 关键商业与运营指标 (KPI & Metrics)
运营后台 (`/api/admin/stats`) 与日常监控需重点观测以下指标：
1. **藏宝阁 VIP 转化率 (CR)**：VIP付费用户数 / 注册用户数，行业及格线 5%，本方案预期目标为 **15% ~ 22%**；
2. **客单价与 ARPU**：以 9.9 元为主力，叠加阶梯充值包；
3. **病毒裂变系数 (K-Factor)**：K = I × C（I 为单用户平均邀请人数，C 为受邀转化率）。若 K > 1，则平台实现自发性病毒裂变式增长；
4. **卡密核销率**：电商渠道卡密的售出与系统内实际核销比例，用于评估电商引流效果。

### 10.2 获客裂变落地建议
- **高校求职社群裂变**：在微信群、QQ 求职群传播邀请短链，借助“注册即送100积分”降低进群门槛；
- **闲鱼/小红书钩子引流**：发布大厂面经复盘笔记，文末附带卡密或专属邀请短链；
- **KOL/校园大使分销**：为校园求职大使定制专属批次卡密（如 `BATCH_TJU_2026`），按核销激活量给予分成结算。

### 10.3 商业化中长期扩展规划
1. **周期性订阅升级（季度卡/年卡）**：
   - 当内容量突破 5,000+ 篇并引入实时在线模考后，可探索“9.9 元月度体验卡” + “29.9 元秋招全程通行证”；
2. **B 端企业直招付费**：
   - 允许优质企业 HR 自助认证，付费置顶校招宣讲公告或置顶官方内推码；
3. **专家付费 1V1 简历润色与模拟面试**：
   - 基于现有积分钱包，开放高阶服务兑换，链接大厂在职学长学姐进行 1V1 辅导。
