## 1. 系统架构与业务定位

### 1.1 业务背景与用户痛点
- **内推信息不对称**：校招信息分散于各大论坛、内推码随处失效，需要一个聚合大厂 HR/员工内推码的高可用清单。
- **民企/外企与央国企分类混杂**：求职者求职意向差异大，体制内偏好者需要专注央企、省属国企与事业单位；市场化求职者偏好高薪外企与互联网独角兽，需要清晰的版块隔离与专属属性标签。
- **面经碎片化与敷衍**：普通论坛面经多为零碎八股，缺乏从简历投递、AI测评、初面到终面的全流程拆解。
- **真题与政策资源获取门槛高**：真题大多夹杂在各网盘与题库中，链接失效、密码遗失极为普遍；各省市人才引进补贴政策分散，缺乏系统汇总。
- **投递直通链接断裂**：以往许多聚合平台由于爬虫字段截断或错误抓取中转链接，导致用户点击投递后频繁报 404 或链接失效，严重损耗用户信任。
- **本系统核心解决点**：建立一个轻量、极速响应、内容真实经过清洗验证的垂直校招求职全功能平台，涵盖真实内推广场、企业校招、央国企校招、收缩至“藏宝阁”的深度面经与通关题库，结合 9.9 元卡通萌龙门禁实现商业闭环。

### 1.3 五大业务版块与全局导航拓扑
系统采用底部自适应 5-Tab 经典布局：
1. **🔥 官方内推广场 (`jobs`)**：以真实员工/HR 内推码为核心，一键复制内推码并直通网申，支持【今日首发】高亮；
2. **🏢 企业校招 (`enterprise`)**：精选 5,112 条优质民企、独角兽、硬科技与外企校招网申直通车；
3. **🏛️ 央国企校招 (`soe`)**：收录 1,350 条央企、地方国企、事业单位、科研院所与金融机构公告，提供专属体制内性质标签；
4. **🏰 藏宝阁 (`treasure`)**：收缩整合“面经复盘”与“真题资料”，配合小蓝龙吉祥物 9.9 元卡通萌龙门禁，开通后全场免积分免费阅读；
5. **👤 我的中心 (`profile`)**：安全隐私展示、积分钱包、邀请裂变短链、在线充值与电商卡密核销。

## 3. 核心业务功能与系统特性全景说明

### 3.1 官方内推广场真实数据全量接入（316 条真实名企内推）
- **数据来源**：腾讯文档多维表格 Tab `BB08J2`（官方内推汇总）。
- **数据体量**：316 家在招名企（如智元机器人、腾讯、沐曦股份、普渡机器人、阿里、美团、大疆、华为等）。
- **核心能力**：
  - 支持一键复制内推码并直通网申；
  - 24 小时内发布的岗位展示【今日首发】高亮徽章；
  - 名企官网直达九宫格便捷入口。

### 3.2 智能防截断与外链中转自动解码引擎
- **外链中转自动剥离**：自动识别 `docs.qq.com/scenario/link.html`、`link-warning` 等中转特征，通过 `decodeURIComponent` 还原纯净的 ATS 真实招聘主页。
- **截断特征识别与阻断**：严格检测 URL 尾部是否带有 `...` 或 `.` 截断字符，对异常链接发出告警阻断入库，确保每一条入库的投递链接均完整可用。
- **投递通道多格式兼容**：自动兼容飞书招聘（`jobs.feishu.cn`）、Moka（`mokahr.com`）、北森（`zhiye.com`）、大易、各大厂招聘官网直链，并自动识别格式化 `mailto:` 邮箱投递通道。

### 3.3 双轨数据同步体系（在线接口与 Worker 定时同步 + 离线托底导入）
为保证数据采集的稳定高可用，系统构建了“线上自动拉取”与“离线文件托底”双轨同步机制：
1. **在线抓取与 Worker 适配链路 (`sync_tencent_smartsheet.mjs` & `ats_adapters.js`)**：封装腾讯文档多维表格在线读取接口，支持传入 Cookie 鉴权凭证直接拉取云端最新数据；
2. **离线与文件托底链路 (`import_smartsheet_file.mjs` & `parse_and_merge_all_har_tabs.py`)**：支持从浏览器导出的 HAR 网络抓包中自动反序列化全量数据。

### 3.4 增强型多维复合排重引擎（`recruitment_type` 维度融入 `dedup_hash`）
将 `recruitment_type`（校招类型）纳入排重唯一键：
`dedup_hash = SHA256(company_name + '_' + job_title + '_' + recruitment_type + '_' + apply_url)`
支持区分同企业同岗位在秋招、春招、日常实习等多批次下的独立展示，彻底杜绝数据主键冲突导致的错误去重。

### 3.5 历史测试数据清理与全量真实数据迁移（`0010_import_real_smartsheet_321_referrals.sql`）
编写并应用全新迁移 `0010_import_real_smartsheet_321_referrals.sql`，前置清理了所有历史示例数据（`job_%`），保证生产库数据纯净。

### 3.6 “企业校招”与“央国企校招”双核心版块上线（5,112 条企业 + 1,350 条央国企）
- **🏢 企业校招专区 (Enterprise)**：
  - 数据源：多维表格 Tab `tny2X0`（“企业网申信息汇总”）；
  - 数据规模：5,112 条在招岗位；
  - 业务定位：覆盖互联网高科技、芯片半导体、新能源汽车、生物医药等新质生产力名企、外企与独角兽；
  - 多维筛选：支持按行业赛道、工作城市、招聘批次（秋招/春招/实习）快速组合筛选。
- **🏛️ 央国企校招专区 (SOE)**：
  - 数据源：多维表格 Tab `tXOMXd`（“校园招聘信息官方平台（国企央企、事业单位）”）；
  - 数据规模：1,350 条权威招考公告；
  - 核心企业溯源：收录了广大求职者关心的“保利科技”、“中国移动”、“中国建筑”、“国家电网”、“中国中车”、“中核集团”以及各大国有银行与重点科研院所；

## 4. 核心设计要点与数据工程架构

### 4.1 腾讯多维表格底层通信协议剖析与 AST 逆向
腾讯多维表格未公开通用 RESTful API，而是通过内部专有协议传输压缩数据流：
1. **网络载荷格式**：通过浏览器开发者工具 Network 面板，捕获请求 `dop-api/opendoc` 或 `dop-api/get/sheet`，其响应体中携带名为 `smartsheet` 的 Base64 编码字符串。
2. **底层解密与反序列化**：RFC 1950 标准的 **ZLIB 二进制压缩流**，通过补齐 Base64 填充后解压：
   ```python
   def b64zlib(b64str):
       pad = (4 - len(b64str) % 4) % 4
       return json.loads(zlib.decompress(base64.b64decode(b64str + '=' * pad)).decode('utf-8'))
   ```
3. **AST 抽象语法树关键节点还原**：
   - `k1`：富文本对象数组，每一项的 `k2` 存储实际文本片段；
   - `k2`：纯文本直接值；
   - `k3`：字段元数据与全局选项字典（包含单选/多选列的枚举项 UUID 与名称对照表）；
   - `k4`：全表格行的有序索引列表（Row Order List）；
   - `k8`：超链接专用对象数组，存储不受页面排版影响的真实超链接 URL；
   - `k9`：单选/多选字段存储的选中项 UUID 列表，需逆向检索 `k3` 还原选项文本。

### 4.4 外链清洗与防截断防中转算法设计
```python
def clean_apply_url(raw_url: str) -> str:
    if not raw_url:
        return ""
    url = raw_url.strip()
    # 1. 剥离腾讯文档外链安全中转提示页
    if "docs.qq.com/scenario/link.html" in url or "url=" in url:
        match = re.search(r"[?&]url=([^&]+)", url)
        if match:
            url = urllib.parse.unquote(match.group(1))
    # 2. 剥离视觉截断产生的残损字符
    if url.endswith("...") or url.endswith(".."):
        return ""
    # 3. 校验合法协议
    if url.startswith("http://") or url.startswith("https://") or url.startswith("mailto:"):
        return url
    return ""
```

### 4.5 全量子表复合哈希与精准增量去重算法
为了支持频繁更新且不覆盖历史已有数据，脚本预先加载数据库现存指纹集合：
- **岗位表去重指纹**：
  `fingerprint = SHA256(company_name.strip() + '_' + apply_url.strip())`
- **面经表去重指纹**：
  `fingerprint = SHA256(company_name.strip() + '_' + title.strip())`
- **资料与政策表去重指纹**：
  `fingerprint = SHA256(title.strip() + '_' + (drive_url or source_url).strip())`
若指纹已存在于数据库中，则自动跳过，严格实现 100% 幂等与零重复。

## 6. 改动的核心注意点与避坑指南（必读复盘 13 大坑）

### 💥 坑 1：在浏览器控制台执行脚本或无头爬虫请求报错 404 / 空数据
- **现象**：浏览器控制台调用腾讯接口频繁 404。
- **根因分析**：腾讯多维表格升级为 `dop-api` 压缩通道且前端为虚拟滚动 DOM。
- **解决方案**：采用全量网络抓包（HAR 导出）反序列化解析。

### 💥 坑 2：提取出的数据全是一堆无规则 base64，普通 json.loads 直接报错
- **现象**：解包出来是乱码二进制。
- **根因分析**：数据使用了 RFC 1950 标准的 ZLIB 压缩。
- **解决方案**：补齐 Base64 填充后使用 `zlib.decompress` 还原。

### 💥 坑 3：Cloudflare D1 远程迁移明明生成了数据，执行却提示 `✅ No migrations to apply!`
- **现象**：修改了已执行过的迁移文件，执行却被跳过。
- **根因分析**：D1 内部表 `d1_migrations` 以文件名为唯一主键记录执行历史。
- **解决方案**：严禁修改历史迁移文件，必须单调递增生成新序号迁移文件（如 `0011`、`0012`、`0013`）。

### 💥 坑 4：Wrangler CLI 在后台执行时报错 `In a non-interactive environment... CLOUDFLARE_API_TOKEN`
- **解决方案**：交互终端执行 `npx wrangler login`，或在 CI/CD 中配置 `CLOUDFLARE_API_TOKEN`。

### 💥 坑 5：Windows PowerShell 运行 Python 脚本时的中文控制台编码异常
- **解决方案**：Python 脚本头部统一注入 `sys.stdout.reconfigure(encoding="utf-8")`。

### 💥 坑 6：多维表格超链接视觉截断与腾讯安全中转页陷阱
- **解决方案**：提取 AST `k8` 真实超链接字段，并在清洗管线中严格剥离 `link.html` 安全中转。

### 💥 坑 7：岗位排重哈希漏掉招聘批次导致的同企业同岗位不同批次覆盖问题
- **解决方案**：排重键纳入 `recruitment_type`（校招类型）。

### 💥 坑 8：Wrangler 4.x 远程迁移非交互式执行挂起（管道 `echo y` 技巧解决阻塞）
- **解决方案**：通过管道注入确认：`echo y | npx wrangler d1 migrations apply ... --remote`。

### 💥 坑 9：线上生产搜不到“智元机器人”与历史假数据残留根因排查
- **解决方案**：前置执行 `DELETE FROM job_referrals WHERE id LIKE 'job_%'` 清理假数据。

### 💥 坑 10：本地与生产测试隔离原则（拒绝未经本地测试直推线上）
- **核心原则**：所有数据迁移与前端变更必须先在本地独立测试环境（`start_local_test.bat`）跑通后方可上线。

### 💥 坑 11：SQLite `SQLITE_TOOBIG` 语句超限报错（上万行数据单条 SQL 生成导致解析器崩溃）
- **现象**：在导入企业校招与央国企校招（数千条数据）时，D1 迁移报错 `SQLITE_TOOBIG: statement too long` 或超出最大变量数限制（`maximum number of host parameters is 32766`）。
- **根因分析**：SQLite 单条 SQL 语句的最大长度与参数个数受限，若将几千条记录拼接在同一个 `INSERT INTO ... VALUES (...), (...)` 中，会导致解析失败。
- **解决方案**：数据生成脚本必须采用**分批切片机制**，每批最多生成 50 条记录的 INSERT 语句，多批次串行提交，彻底规避该限制。

### 💥 坑 12：HAR 文件更新路径分散与手动拷贝易错问题
- **现象**：用户重新从腾讯文档导出 `docs.qq.com.har` 后通常默认保存在浏览器的 `Downloads` 文件夹，每次手动找路径拷贝容易出错或遗漏。
- **解决方案**：在 `update_and_deploy_har.bat` 中加入智能探测逻辑，优先检测 `%USERPROFILE%\Downloads\docs.qq.com.har`，若存在则自动拷贝覆盖至 `seeds/docs.qq.com.har`，免去人工移动文件的繁琐操作。

### 💥 坑 13：“保利科技”等央国企校招数据来源溯源说明
- **背景疑问**：在旧版官方内推子表中检索不到“保利科技”，引发数据来源疑问。
- **事实依据**：“保利科技”来源于多维表格的第 3 个子表：`tXOMXd`（“校园招聘信息官方平台（国企央企、事业单位）”）。该子表专门收录体制内企事业单位官方直招信息，现已全量归入“央国企校招”专区。

## 8. 后续系统演进路线与维护建议

1. **多维表格定时无头自动同步（免人工导出 HAR）**：
   结合 Cloudflare Workers 的定时 Cron 机制（`scheduled` 事件），在 `worker/index.js` 中接入 `ats_adapters.js` 的 `normalizeSmartsheetItem`，配合腾讯文档只读授权 Token，实现每周全自动拉取与入库。
2. **失效链接全自动心跳探测**：
   针对各招聘官网和内推链接可能存在“岗位已下线”、“招满关闭”的情况，可编写异步心跳 Worker，每月轮询一次所有 `apply_url`，若返回 HTTP 404 或特定下线关键字，自动更新 `status = 'closed'`，避免求职者无效跳转。
3. **数据库全文检索优化 (FTS5)**：
   当前查询基于 SQL `LIKE %q%`，随着数据规模突破 6,700+ 岗位，可在 Cloudflare D1 中开启 SQLite `FTS5` 虚拟表，实现毫秒级分词模糊搜索与精准高亮匹配。
4. **积分消费事务强一致性保障**：
   在用户兑换面经与下载真题资料时，前端已接入 `points_required` 校验；后续可将“积分扣除 + 权限记录生成”封装入 D1 单事务（`db.batch([deductPoints, recordUnlock])`），确保高并发下数据绝对强一致。
