# 校招内推与名企招聘网：全栈开发架构、多维表格数据清洗与部署避坑指南

> **核心摘要**：本系统旨在为广大校招应届生与求职者提供一站式的“名企内推直通车”、“大厂深度面经复盘”与“校招真题与解题资料库”。本文档记录了从零搭建本系统的全套工程实践，重点拆解基于腾讯文档多维表格的高难度数据采集、二进制 ZLIB 逆向解压清洗、Cloudflare Serverless 边缘部署、D1 关系型数据库管理，以及整个开发过程中踩坑与解决的核心经验。

---

## 1. 系统架构与开发思路

### 1.1 业务背景与定位
- **内推信息不对称**：校招信息分散于各大论坛、内推码随处失效，需要一个聚合大厂 HR/员工内推码的高可用清单。
- **面经碎片化与敷衍**：普通论坛面经多为零碎八股，缺乏从简历投递、AI测评、初面到终面的全流程拆解。
- **真题资源获取门槛高**：真题大多夹杂在各网盘与题库中，链接失效、密码遗失极为普遍。
- **本系统核心解决点**：建立一个轻量、极速响应、内容真实经过清洗验证的垂直校招求职工具平台，涵盖岗位内推、深度流程面经与附带真实提取码的题库网盘。

### 1.2 整体技术架构（Edge Serverless）
采用去中心化、低成本、高并发的边缘云原生全栈架构：
```text
┌─────────────────────────────────────────────────────────────┐
│                      用户浏览器 (Client)                      │
│        React 19 + Vite 8 SPA (响应式移动端/PC自适应UI)         │
└──────────────────────────────┬──────────────────────────────┘
                               │ HTTPS / API

┌─────────────────────────────────────────────────────────────┐

│  - Assets 静态资源托管 (单页面应用路由分发)                   │

                               │
                               ▼
```

## 4. 数据采集与清洗全流程（核心数据工程）

数据来源于腾讯文档多维表格：`https://docs.qq.com/smartsheet/DRmRGYk14dW53VHdS`

### 4.1 核心数据结构与子表映射表

| :--- | :--- | :--- | :--- | :--- |

### 4.2 腾讯多维表格底层传输协议剖析
腾讯文档多维表格的数据获取之所以常规脚本/爬虫会失败，是因为其采用了以下私有通信规范：
1. **传输载荷加密/压缩**：
   数据接口主要为 `dop-api/opendoc` 与 `dop-api/get/sheet`，返回的有效载荷 `smartsheet` 是一段 Base64 编码的字符串。
2. **底层解密算法**：
   该 Base64 字符串解码后为原生的 **ZLIB 二进制压缩流**。
   必须先补齐 Base64 填充位后解码，再使用 `zlib.decompress()` 解包，方可得到由 AST 抽象语法树构成的内部 JSON 结构。
3. **复杂单元格 AST 节点编码规则**：
   - `k1`: 纯文本片段数组（RichText AST），需合并各子对象的 `k2`。
   - `k2`: 单文本字符串。
   - `k3`: 单元格字段定义及全局选项元数据（Options Schema）。
   - `k4`: 行记录排序数组（Row Order List）。
   - `k8`: 超链接对象数组（其 `k3` 或 `k2` 存储真实目标 URL）。
   - `k9`: 单选/多选字段的选项 UUID 列表，必须通过 `k3` 的字段选项映射字典逆向回查真实文本。

### 4.3 数据清洗与提取算法
清洗器核心代码位于 `frontend/scripts/parse_har_export.py` 与 `frontend/scripts/import_experiences_and_resources.mjs`：
1. **网盘链接与提取码提取**：
   ```javascript
   const urlMatch = text.match(/https?:\/\/[^\s\u4e00-\u9fa5<>'\"\uff0c,)]+/)
   const codeMatch = text.match(/(?:提取码|密码|访问码|code)[：:\s]*([a-zA-Z0-9]{4,8})/i)
   ```
2. **文件格式智能推断**：
   根据标题及链接特征智能匹配为 `PDF 文档`、`Excel 题库`、`ZIP 资料包`、`在线答题试卷`、`百度网盘资源`、`夸克网盘资源` 等。
3. **防重入唯一 ID 生成**：
   - 面经：`exp_real_{index}_{SHA256(公司_岗位_标题)[:12]}`
   - 资料：`res_real_{index}_{SHA256(标题_下载链接)[:12]}`
   - 保证后续多次导入时均可幂等执行 `INSERT OR REPLACE`。

## 5. 日常数据增量同步与更新操作规范（SOP）

当运营人员在腾讯多维表格中新增了面经或题库，如何同步到线上？

### 极速 3 步更新流水线：
1. **导出最新 HAR 文件**：
   - 浏览器打开目标腾讯多维表格。
   - 按 `F12` 打开开发者工具，切换到 `Network`（网络）面板。
   - 依次点击底部的所有 Tab 子表（如“⛽大厂面试经验总结【上岸版】”、“校招资料库（题库）”、“⛽面试真题答题思路”、“互联网大厂真题合集”），使浏览器加载各表数据。
   - 在 Network 面板空白处右键选择 **“Save all as HAR with content”**（导出包含内容的 HAR）。
   - 将导出的文件重命名并覆盖保存到项目根目录的 `seeds/docs.qq.com.har`。
2. **执行自动化清洗与生成 SQL 迁移**：
   ```powershell
   python frontend/scripts/parse_har_export.py
   npm run import:resources
   ```
   *控制台将打印清洗出的真实面经与真题条数，并自动生成最新的 D1 SQL 迁移文件。*
3. **部署至生产环境**：
   ```powershell
   cd frontend
   npm run db:migrate:remote
   npm run deploy
   ```

## 6. 开发中踩过的核心大坑与最终解决方案（必读复盘）

本节是本项目最重要的经验积累，下个开发阶段务必先查阅此清单，避免重复踩坑：

### 💥 坑 1：在浏览器控制台执行脚本或无头爬虫请求报错 404 / 空数据
- **现象**：在浏览器 F12 控制台尝试调用接口获取数据，频繁报错 `smartsheet/get_sheet_data 404`，下载的 `experiences_and_resources.json` 数据为空（`sheets: {}`）。
- **根因分析**：
  1. 腾讯文档最新前端架构全面升级为 `dop-api`，不再向后兼容旧的 `get_sheet_data` REST 接口。
  2. 页面采用虚拟表格（Virtual Scrolling / Canvas DOM），只有当前视口内可见的几十行才存在于 DOM 中，直接写 JS 遍历 DOM 节点会导致 90% 以上数据截断。
- **最终解决方案**：
  放弃 DOM 抓取与模拟 API 调用，采用**全量网络抓包（HAR 文件导出）方案**。浏览器在切换 Tab 时已通过 WebSocket / fetch 加载了全量分块，直接抓取 HAR 既拥有完整的原始载荷，又完美规避账号鉴权失效、反爬拦截等问题。

### 💥 坑 2：提取出的数据全是一堆无规则 base64，普通 json.loads 直接报错
- **现象**：HAR 中抓到了 `smartsheet` 字段，但 Base64 解码后是一串无法识别的乱码二进制，无法直接解析成 JSON。
- **根因分析**：
  腾讯多维表格为节省带宽，对复杂表格使用了二进制压缩流传输。
- **最终解决方案**：
  编写专用的解包函数：
  ```python
  def b64zlib(b64str):
      pad = (4 - len(b64str) % 4) % 4
      return json.loads(zlib.decompress(base64.b64decode(b64str + "=" * pad)).decode("utf-8"))
  ```
  结合其内部 AST（`k1`, `k2`, `k8`, `k9` 选项字典）完成全字段结构化复原。

### 💥 坑 3：Cloudflare D1 远程迁移明明生成了 1386 条数据，执行却提示 `✅ No migrations to apply!`
- **现象**：本地测试已成功生成 4.7MB 的迁移 SQL，但在终端执行 `wrangler d1 migrations apply ... --remote` 时，终端直接显示 `✅ No migrations to apply!`，线上数据依然为空或未更新。
- **根因分析（重大陷阱）**：
  Cloudflare D1 数据库在初始化时会建一张 `d1_migrations` 内部表，**以迁移文件的文件名作为唯一标识（Primary Key）记录执行状态**。
  - 在前期联调阶段，如果 `0008` 曾被执行过（哪怕当时文件内容是空的或者只有两句 `DELETE` 语句），D1 就会永久记录 `0008` 为已执行。
  - 之后无论本地怎么修改 `0008` 的内容，Wrangler 在对比线上记录时只要发现 `0008` 已在表中，就会**无条件完全跳过该文件**！
- **最终解决方案**：
  **必须单调递增生成全新序号的迁移文件**！
  将迁移文件命名升级为 `0009_import_real_experiences_and_resources.sql`。Wrangler 识别到全新的迁移版本 `0009`，便会立即全量执行并应用这 1,389 条真实数据。
  > **核心避坑准则**：在 Cloudflare D1 开发中，**永远不要就地重写已经 apply 过的同名 migration 文件**，任何数据结构变更或批量增量导入，必须严格生成新的递增版本号（如 `0009`, `0010`）。

### 💥 坑 4：Wrangler CLI 在后台执行时报错 `In a non-interactive environment... CLOUDFLARE_API_TOKEN`
- **现象**：在无图形界面的子进程或非交互终端中运行 wrangler 远程操作报错，或者 OAuth Token 过期导致拒绝操作。
- **根因分析**：
  Wrangler 的本地 OAuth 刷新凭证存放在 `C:\Users\zhoux\AppData\Roaming\xdg.config\.wrangler\config\default.toml`，存在有效期限制，且无法在无用户介入的自动化子环境中弹出网页授权。
- **最终解决方案**：
  对于生产环境的远程部署操作，直接在用户的交互式终端（PowerShell）中执行：
  ```powershell
  npx wrangler login
  npm run db:migrate:remote
  ```
  通过官方流程在浏览器中点一次“确认授权”，即可为本地环境续期 30~90 天。

### 💥 坑 5：Windows PowerShell 运行 Python 脚本时的中文控制台编码异常
- **现象**：Python 打印公司名称时输出乱码，甚至在字符串含有特殊符号时引发 `SyntaxError: unexpected character after line continuation character`。
- **根因分析**：
  Windows PowerShell 默认的编码页通常为 `GBK` 或 `CP936`，在打印包含复杂 UTF-8 符号时发生截断。
- **最终解决方案**：
  所有数据清洗与脚本头部统一加上显式 UTF-8 声明：
  ```python
  import sys
  sys.stdout.reconfigure(encoding="utf-8")
  ```

## 7. 后续系统演进路线与维护建议

1. **数据库全文检索优化**：
   当前搜索基于 SQL `LIKE %q%`，随着真实真题数据增长突破 5000+ 条，建议在 D1 中开启 `FTS5`（Full-Text Search 5）虚拟表索引，以支持毫秒级全文模糊匹配与分词高亮。
2. **网盘有效性自动探测心跳**：
   针对百度网盘、夸克网盘链接易失效问题，可编写定时 Worker，每周异步校验一次 `drive_url` 的 HTTP 状态码，发现失效链接自动在后台打标告警。
3. **积分消费事务严谨性**：
   在用户兑换面经与下载真题资料时，前端已接入 `points_required` 校验；后续可将“积分扣除 + 权限记录生成”封装入 D1 单事务（`db.batch([deductPoints, recordUnlock])`），确保数据绝对强一致。
